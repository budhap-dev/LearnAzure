## Why this matters

> [!SCENARIO] The blank page and the wrong name
> Ana ships the shop at 17:40 on a Friday. By Saturday morning support has forty tickets, all the same: a white page. Bengaluru is worst hit. Dev finds the cause in the Front Door logs. A rule added in the spring to lift the cache hit ratio keeps every file from the shop's origin for 24 hours, `index.html` included. The cached HTML still asks for `index-4f9a2c.js`, and Friday's deploy removed it.
>
> Then a customer emails a screenshot. The home page says "Welcome back, Sarah". Her name is Meera. A flash-sale tweak had marked the personalised `/api/home` response `public`, and for forty minutes the edge served one shopper's greeting to others.

Both incidents have one cause. ==An edge cache does exactly what the headers and rules tell it, so every response needs a deliberate answer to "who may store this, and for how long?"==

## Two kinds of file, two cache rules

**[Content hashing](gl:content-hashing)** names each JavaScript and CSS file after a hash of its contents, such as `index-4f9a2c.js`. Change one line and the name changes, so a hashed URL can be cached for a year. `index.html` is the opposite: its name never changes, yet it says which bundles are current. Cache it for a day and customers are pinned to yesterday's release, and to a blank page once its bundles are gone.

The **[Cache-Control header](gl:cache-control-header)** carries the decision for the browser and Front Door alike.

| Response | Cache-Control |
|---|---|
| Hashed `/assets/*` | `public, max-age=31536000, immutable` |
| `index.html` and deep links | `no-cache` (revalidate every time) |
| Anything with a user in it | `private, no-store` |
| Product images | a long `max-age` on versioned URLs |

On [Static Web Apps](gl:static-web-apps) these go in `staticwebapp.config.json`, with one trap. Route rules are not applied to requests answered by the [navigation fallback](gl:navigation-fallback), so a deep link such as `/orders/4821` gets only `globalHeaders`. Put the HTML policy there and override it for the hashed folder:

```json
{
  "globalHeaders": { "Cache-Control": "no-cache" },
  "routes": [
    { "route": "/assets/*", "headers": { "Cache-Control": "public, max-age=31536000, immutable" } }
  ]
}
```

**[Cache purge](gl:cache-purge)** removes copies from every [point of presence](gl:point-of-presence): one path, or a whole domain with `/*`. It takes up to ten minutes. Microsoft's own advice is to version assets at new URLs and keep purge for emergencies. Needing to purge bundles means your hashing is broken.

A tab opened before the release still asks for old chunks when it lazy-loads a route; catch that error and reload once.

## Front Door in front of Static Web Apps

Static Web Apps already serves files from a global edge ([lesson 2.3](lesson:2.3)). There are two ways to add [Azure Front Door](gl:azure-front-door). **Enterprise-grade edge** is a Standard-plan checkbox: Microsoft runs Front Door for you, with no [web application firewall](gl:web-application-firewall) and no rules of your own. Or you put **your own Front Door profile** in front. Northline did that in [lesson 4.2](lesson:4.2), for the WAF and one entry point for the shop, API and images.

That makes Static Web Apps the **[origin server](gl:origin-server)**, and Front Door's [edge cache](gl:edge-cache) is the one that bites. Lock the origin down: in `staticwebapp.config.json`, allow only the `AzureFrontDoor.Backend` service tag and require your profile's `X-Azure-FDID` header.

How Front Door decides, per Microsoft's documentation:

- It honours `s-maxage`, then `max-age`, then `Expires`. **With no header at all, it caches for a random one to three days.**
- It never caches `private`, `no-cache` or `no-store`, even when a rule says to.
- A request with an `Authorization` header is not cached unless the response says `public`, `s-maxage` or `must-revalidate`. That is how "Sarah" escaped.
- The **[cache key](gl:cache-key)** is the path plus all, some or none of the query string. Never the cookie or the token, so every shopper asking for `/api/home` shares one key.

A **[Front Door rule set](gl:front-door-rule-set)** changes this per request: match on path or header, then override caching, change the cache key or rewrite the URL. Rules are invisible to whoever reads the app's code. Friday's culprit was "override always, 24 hours" on `/*`.

==Turn caching off on the API route, and opt in only the endpoints that are identical for every shopper.== The catalogue can sit at the edge with a short `s-maxage`, or use [output caching](gl:output-caching) in Redis. Anything shaped for one person, including a [backend for frontend](gl:backend-for-frontend) response, sends `private, no-store`.

## Compression, images and Core Web Vitals

**[Compression](gl:compression)** in Front Door is a route setting that works only with caching on. It uses Brotli, or gzip for older browsers, on files of 1 KB to 8 MB whose MIME type is on an editable list. Text shrinks dramatically; JPEG and WebP barely change.

Front Door has no image service, unlike Cloudflare or Vercel. Make WebP or AVIF variants yourself, at build time or on upload ([lesson 11.6](lesson:11.6)), and give every image a width and height.

All of this shows in **[Core Web Vitals](gl:core-web-vitals)**, judged at the 75th percentile of real page loads: Largest Contentful Paint 2.5 seconds or less, Interaction to Next Paint (which replaced First Input Delay in March 2024) 200 ms or less, and Cumulative Layout Shift 0.1 or less. Lighthouse is the lab view. For the field view, send `web-vitals` numbers to [Application Insights](gl:application-insights) and split by country: Bengaluru on 4G is not London on fibre.

## In practice

Ana's fix, in one pull request:

- **Static Web Apps:** `no-cache` globally; a year and `immutable` for `/assets/*`.
- **Front Door:** the spring rule deleted; compression on; caching disabled on `/api/*` except `/api/catalogue/*`.
- **Node API:** middleware defaults every response to `private, no-store`; catalogue handlers opt in to `public, s-maxage=60`.
- **Pipeline:** after each deploy, checks that a hashed bundle returns `X-Cache: TCP_HIT` and `/api/home` does not.

Bengaluru's 75th-percentile LCP falls from 4.1 to 2.3 seconds.

**What it costs.** The Front Door Premium base fee (about $330 a month) is already paid; traffic is charged per GB and per request, which compression reduces. The expensive mistakes are not on the bill: a day of blank pages, and a privacy incident.

**What breaks.**

- **A missing header:** one to three days at the edge.
- **`public` on a personal response:** the token does not protect you.
- **Legacy CDNs:** Azure CDN Standard from Microsoft (classic) takes no new profiles and retires on 30 September 2027; Azure CDN from Edgio shut down in January 2025. Move to Front Door Standard or Premium.

## Guiding your team

> [!TEAM]
> Before a release or a Front Door change, ask:
>
> 1. **What Cache-Control header does each kind of response send?** A missing header means days at the edge.
> 2. **Which rule sets override the origin, and on which paths?** Rules are invisible in the app's code, so someone must own them.
> 3. **Can any cached response contain a name, a basket or an order?** If yes, it must be `private, no-store`.
> 4. **What happens to a tab opened before the release?** Old chunks disappear, so plan for a reload.
> 5. **What are our field Core Web Vitals in Bengaluru?** Lab scores on office Wi-Fi hide the customers you are losing.

## Key takeaways

- Hashed assets get a year and `immutable`; `index.html` gets `no-cache`, set in `globalHeaders` because fallback responses skip route rules.
- Front Door never caches `private`, `no-cache` or `no-store`, and caches for one to three days when there is no header.
- The cache key is the path and query string, never the user. Disable caching on the API route.
- Versioned URLs are the real invalidation; purge is for emergencies.
- Front Door compresses only with caching on, and does not resize images.
- Measure Core Web Vitals from real users at the 75th percentile, split by country.
