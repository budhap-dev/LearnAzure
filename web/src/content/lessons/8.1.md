## Why this matters

> [!SCENARIO] "We need an AI strategy by the board meeting"
> The CEO is back from a retail conference where every talk was about AI. By Monday, a whiteboard in the office has six ideas on it: a shopping assistant that answers questions about products and orders; descriptions written for the 40,000 products that have none; supplier invoices read automatically instead of typed in by three people; search that understands "warm waterproof jacket for a six-year-old"; a forecast of demand per store; and Copilot for everyone in head office.
>
> Priya is asked which Azure AI service to buy. Dev has already built a chatbot demo over a weekend. Finance wants to know what it will cost. Nobody has asked which of the six ideas is worth doing first.

## Five kinds of AI, five kinds of tool

"AI" on that whiteboard covers at least five different kinds of work, each with a different tool, price and risk. Sorting the ideas into them is most of the strategy.

- **Buy it.** Some AI is a finished product. **[Microsoft 365 Copilot](gl:microsoft-365-copilot)** works inside Word, Outlook and Teams over data the organisation already has; GitHub Copilot does the same for code. You pay per user and configure it. There is nothing to build.
- **Configure it.** **[Microsoft Copilot Studio](gl:microsoft-copilot-studio)** builds conversational agents with little or no code, from documents, websites and connectors. It is good for internal helpdesks and simple customer questions.
- **Call a prebuilt service.** Reading an invoice, transcribing a call, translating a page and spotting a face are well-defined *perception* tasks. **Azure AI Services** do them through an API, priced per page, minute or character ([lesson 8.4](lesson:8.4)).
- **Build with generative AI.** **[Generative AI](gl:generative-ai)** produces new text, code or images. At its heart is a **[large language model](gl:large-language-model)** (LLM), a model that has learnt from vast amounts of text to predict what comes next. It can summarise, draft, classify, extract and reason over whatever you give it. On Azure you reach these models through **Azure OpenAI** and the wider **Foundry Models** catalogue ([lesson 8.2](lesson:8.2)). You build with them in **Microsoft Foundry** ([lesson 8.3](lesson:8.3)), and ground them in your own data with **Azure AI Search** ([lesson 8.5](lesson:8.5)).
- **Train your own model.** Predicting a number or a category from your own history, such as demand per store, churn or fraud, is classic machine learning. **[Azure Machine Learning](gl:azure-machine-learning)** is the platform for it. It needs data scientists, clean historical data and a way to retrain.

==Most business ideas labelled "AI" are one of these five. Name the kind first, and the service, the cost and the risk follow.==

| Idea on the whiteboard | Kind | Where it lands | Lesson |
|---|---|---|---|
| Copilot for head office | Buy | Microsoft 365 Copilot | - |
| Read supplier invoices | Prebuilt | Document Intelligence | [8.4](lesson:8.4) |
| Write 40,000 product descriptions | Generative | An Azure OpenAI model, run as a batch | [8.2](lesson:8.2) |
| Search that understands meaning | Retrieval | Azure AI Search, hybrid and semantic | [8.5](lesson:8.5) |
| Shopping assistant | Generative + retrieval + tools | A Foundry agent over AI Search and the orders API | [8.6](lesson:8.6) |
| Demand forecast per store | Train your own | Azure Machine Learning | - |

## Inference, not training

The most useful fact for sizing any of this: ==you will almost never train a large model. You call one that already exists, and pay for each call.== Running a trained model to get an answer is **[inference](gl:inference)**. To your code, an LLM behaves like a stateless function: text in, text out. It remembers nothing between calls, is priced per token (roughly three-quarters of a word), and can be confidently wrong. Everything in this module, from prompts and retrieval to agents and evaluation, is about controlling what goes into that function and checking what comes out.

## In practice

Priya's answer to the board is an order of work, not a product:

1. **Invoices first.** Document Intelligence's prebuilt invoice model costs about a cent per page, so three people's typing becomes a review queue. The saving is easy to measure and the risk is low.
2. **Product descriptions next.** Tens of millions of tokens through a small model as a batch job, for well under a hundred dollars, with a human approving each description before it goes live.
3. **Search, then the assistant.** Better search is useful on its own, and the assistant needs it anyway, because an assistant is only as good as what it can retrieve.
4. **Buy Copilot for a pilot group**, at about $30 per user per month, and measure use before rolling it out.
5. **Park the forecast** until someone owns the sales data and it is clean enough to learn from.

**What breaks.**

- **Starting with the chatbot.** It is the hardest idea to get right and the easiest to demo. Dev's weekend demo answered well until someone asked about a real order.
- **Proof of concept, then nothing.** A demo takes a day. Evaluation, safety, cost controls and monitoring take the other ninety percent ([lessons 8.7](lesson:8.7) and [8.8](lesson:8.8)).
- **Shadow AI.** Staff paste customer data into consumer chatbots because nothing approved exists. Providing an approved tool is the fix, not a memo.
- **No owner for quality.** Answers from a model drift as data, prompts and models change. Someone has to watch them, like any other production system.

## Map it to what you know

| You already know | In Azure AI |
|---|---|
| Buy, configure or build, for any system | Copilot, Copilot Studio, or Foundry |
| A third-party API such as Stripe or SendGrid | An AI service or a model endpoint: a call, a key or identity, a bill per use |
| A pure function in Node | An LLM call: stateless, input to output, but not deterministic |
| An npm package someone else maintains | A prebuilt model: someone else trained it, you just call it |
| SQL Server Analysis Services data mining | Azure Machine Learning, for models trained on your own data |

## Guiding your team

> [!TEAM]
> When someone proposes "adding AI":
>
> 1. **Which of the five kinds is this?** Buy, configure, prebuilt, generative, or train our own.
> 2. **What does it replace, and how will we measure that it is better?**
> 3. **What happens when it is wrong?** Who sees the mistake, and how much does it cost?
> 4. **What data does it need, and are we allowed to send it there?**
> 5. **What does it cost at real volume**, not in the demo?

## Key takeaways

- "AI" covers five kinds of work: buy (Microsoft 365 Copilot), configure (Copilot Studio), prebuilt services, generative AI built in Foundry, and custom models in Azure Machine Learning.
- Name the kind first; the service, the price model and the risk follow from it.
- Large language models generate and reason over text. You call them for inference and pay per token; you almost never train them.
- An LLM call is stateless and not deterministic, so prompts, retrieval, safety and evaluation are where the real work is.
- Start with ideas that are measurable and low-risk, such as reading documents, before ideas that are impressive, such as a chatbot.
