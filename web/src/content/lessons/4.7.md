## Why this matters

> [!SCENARIO] "Are we secure?" - 38%, apparently
> The shop's cyber-insurance renewal asks for evidence of its security posture. The finance director forwards it to Priya with one line: "Are we secure?"
>
> Dev opens Microsoft Defender for Cloud for the first time. The secure score is 38%, with 214 recommendations. Worse, he finds an alert from three weeks ago - *anomalous access to a storage account from a Tor exit node* - that went to an email alias nobody reads.
>
> Priya does not need 214 fixes by Friday. She needs a baseline the insurer recognises, an order to work through it, and a person who sees the next alert within the hour.

## Posture, threats and response

Security operations on Azure are three separate jobs, and the products map onto them:

| Job | The question | Service |
|---|---|---|
| **Prevent** by enforcing rules | "Can this be created at all?" | [Azure Policy](gl:azure-policy) |
| **Posture** | "Is what we have configured safely?" | **[Microsoft Defender for Cloud](gl:microsoft-defender-for-cloud)**: [cloud security posture management](gl:cloud-security-posture-management) and the secure score |
| **Detect** | "Is someone attacking it right now?" | Defender for Cloud's paid **Defender plans**, per resource type |
| **Respond** | "What happened across everything, and what do we do?" | **[Microsoft Sentinel](gl:microsoft-sentinel)**, a [SIEM](gl:siem) |

Most organisations need the first three early and the fourth later. ==Turn on posture management everywhere for free, pay for threat detection where the data is, and adopt a SIEM only when someone will watch it.==

## The baseline and the secure score

Defender for Cloud assesses every subscription against the **[Microsoft cloud security benchmark](gl:microsoft-cloud-security-benchmark)** (MCSB), Microsoft's baseline of controls - identity, network, data protection, logging, backup - mapped to CIS, NIST and PCI DSS. It is assigned automatically as an Azure Policy initiative, which is why recommendations and policy compliance tell the same story.

The **[secure score](gl:secure-score)** is the share of those controls you meet, weighted by importance. It is a compass, not a destination. Work by control, highest value first:

1. **Identity**: MFA for everyone, no standing Owners ([lessons 4.4](lesson:4.4) and [4.5](lesson:4.5)).
2. **Exposure**: public endpoints on data services, management ports on the internet ([4.1](lesson:4.1), [4.3](lesson:4.3)).
3. **Data**: encryption in transit, soft delete and backup ([lesson 3.6](lesson:3.6)).
4. **Logging**: diagnostic logs to the [Log Analytics workspace](gl:log-analytics-workspace).

Some recommendations will not fit - a public storage account that serves images through a CDN on purpose. **Exempt** those with a written reason and an expiry date, rather than leaving them to drag the score down forever.

The **regulatory compliance** view maps the same assessments to standards such as ISO 27001 or PCI DSS; that page, exported, is the evidence the insurer is asking for. The paid **Defender CSPM** plan, about $5 per resource per month, adds **attack path analysis**: it chains findings together, such as *internet-facing VM with a critical vulnerability, whose managed identity can read the storage account holding customer data*, which is a far better to-do list than 214 separate items.

## Defender plans: threat detection per resource type

Posture says a door is unlocked. **Defender plans** notice someone walking through it. Each is switched on per subscription and resource type and priced per resource:

| Plan | Detects, for example | Rough price |
|---|---|---|
| Servers (P1 / P2) | Malware and suspicious processes via Defender for Endpoint; vulnerabilities; P2 adds **[just-in-time VM access](gl:just-in-time-vm-access)** | About $5 / $15 per server per month |
| Storage | Unusual access, data exfiltration, malware uploaded to blobs | About $10 per account per month, plus malware scanning per GB |
| Databases (SQL) | SQL injection attempts, brute force, access from unusual locations | About $15 per server per month |
| Key Vault, Resource Manager, App Service | Unusual secret reads, suspicious management operations, attacks on web apps | Small, usage-based or per instance |

Alerts are only as good as their routing. Send them to an on-call rotation, not an alias - through **workflow automation** to Teams or a paging tool - and give each one an owner.

## Sentinel: a SIEM, and a team to go with it

A **SIEM** collects security logs from everywhere - Entra ID sign-ins, the [activity log](gl:activity-log), Defender alerts, firewalls, Microsoft 365 - and correlates them into **incidents**: one attacker's password spray, sign-in and data download become one story instead of three unrelated alerts. Sentinel is Microsoft's cloud SIEM, built on a Log Analytics workspace, with analytics rules, an investigation graph and **playbooks** (Logic Apps) that respond automatically, such as disabling a user or isolating a VM.

It is priced by data ingested - roughly $4 to $5 per GB on pay-as-you-go, less on commitment tiers, with some Microsoft sources free - so a verbose firewall can become the largest line on the bill. And it needs people: analytics rules to tune, incidents to triage, at 3am as well. A small company without a security team usually gets more from a **managed detection and response** service, or Microsoft's own Defender Experts, than from a Sentinel workspace nobody opens.

## In practice

Priya's plan for the shop:

- Foundational CSPM on every subscription, with MCSB; aim for a secure score above 70% within a quarter, working identity and exposure first.
- Defender plans for Storage, Databases, Key Vault and Resource Manager, and Servers P1 for the warehouse VM - roughly $100 a month in total. Just-in-time access is unnecessary because Bastion already replaced open RDP.
- Azure Policy moving from *Audit* to *Deny*, with exemptions, for: data services with public network access, resources outside UK South and UK West, and resources without an owner tag.
- Alerts routed to a Teams channel and the on-call phone through workflow automation.
- No Sentinel yet. Revisit if PCI DSS scope grows, or when there is a security team or partner to run it.
- The regulatory compliance report, exported, goes to the insurer.

**What breaks.**

- **Chasing 100%.** Effort goes into the easiest points, not the biggest risks. Work by control and use exemptions honestly.
- **Alerts to nobody.** A three-week-old alert is a post-mortem, not a detection.
- **Deny on day one.** A new Deny policy breaks every pipeline that relied on the old behaviour. Audit first, fix, then Deny.
- **Every plan on every resource.** Servers P2 on a large VM estate or Defender CSPM on thousands of resources is a real bill; enable plans where the data and the risk are.
- **Sentinel ingesting everything.** Verbose logs at $5 per GB add up fast. Filter with data collection rules and send low-value logs to cheaper tiers.

## Map it to what you know

| You already know | On Azure |
|---|---|
| A CIS benchmark or a Group Policy security baseline | The Microsoft cloud security benchmark, enforced with Azure Policy |
| A Nessus or Qualys vulnerability scan | Defender for Servers' vulnerability assessment and Defender CSPM |
| Antivirus and EDR on every laptop | Defender for Servers, which includes Defender for Endpoint |
| Splunk or QRadar in a SOC | Microsoft Sentinel |
| `npm audit` and Dependabot alerts | The same instinct, applied to cloud configuration |
| A pen test once a year | Continuous posture assessment, plus the pen test |

## Guiding your team

> [!TEAM]
> Every quarter, ask:
>
> 1. **What is the secure score by control, and which three controls do we fix next?**
> 2. **Where do Defender alerts go, and how long did the last one take to be seen?**
> 3. **Which Defender plans are on, and are they where our data actually is?**
> 4. **Which policies are still Audit that should be Deny, and which exemptions have expired?**
> 5. **Who would investigate an incident at 3am?** If the answer is nobody, a SIEM is not the next purchase - a partner is.

## Key takeaways

- Four jobs: Azure Policy prevents, Defender for Cloud posture management assesses, Defender plans detect, Sentinel correlates and responds.
- Foundational CSPM and the Microsoft cloud security benchmark are free: turn them on everywhere and use the regulatory compliance view as evidence.
- The secure score is a compass. Work by control - identity, exposure, data, logging - and exempt honestly.
- Defender plans are priced per resource; enable them where the data and risk are, and route alerts to people who will act.
- Sentinel is a SIEM priced by data ingested and useful only with a team or partner to run it.
- Move policies from Audit to Deny once the estate complies, so the baseline cannot drift.
