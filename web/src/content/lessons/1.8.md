Read it left to right. A shopper hits **Azure Front Door**, which terminates TLS at the nearest edge, filters attacks and routes to the React bundle on [Static Web Apps](gl:static-web-apps). The React app calls the Node API on [App Service](gl:app-service), which reads its [connection string](gl:connection-string) from [Key Vault](gl:key-vault) and talks to [Azure SQL Database](gl:azure-sql-database). Product images come straight from a [storage account](gl:storage-account). Every request leaves a trace in [Application Insights](gl:application-insights), stored in a [Log Analytics workspace](gl:log-analytics-workspace). Staff sign in with the [Microsoft Entra ID](gl:microsoft-entra-id) tenant the company already has.

The React Native app is not a separate design: it is another client of the same API, signed in the same way.

Front Door is the one box to add later. Static Web Apps already has a global CDN and a free certificate; add Front Door when you need a web application firewall, routing rules or a second region. Until then it is £30 a month of nothing.

==A good first Azure design is boring: managed services, one resource group, one region, secrets in a vault and a trace on every request.==

## Every resource, and why

This is what the deployment leaves behind in `rg-shop-prod`. The last column is the sentence to say when someone asks "why that?".

| Resource | Purpose | Why this service |
|---|---|---|
| ![Plan](az:app-service-plan) [App Service plan](gl:app-service-plan) `plan-shop-prod` | The Linux compute the API runs on | **This is what you pay for.** Apps are free tenants on the plan. Size the plan, not the app. |
| ![App Service](az:app-service) App Service `app-shop-api-prod` | The Node API | Microsoft patches Linux and Node; you deploy. Autoscale rules live on the plan. |
| ![Slots](az:web-slots) [Deployment slot](gl:deployment-slot) `staging` | Warm copy of the API | Deploy, smoke-test, **swap** into production with no downtime. Swap back if it breaks. |
| ![SWA](az:static-web-apps) Static Web Apps `swa-shop-web-prod` | The React bundle | Free tier, global CDN, HTTPS and a GitHub Actions workflow generated for you. |
| ![SQL](az:azure-sql) Azure SQL Database `sql-shop-prod` | Orders, customers, stock | Same T-SQL, automated backups, point-in-time restore. Tom keeps his schema. |
| ![Key Vault](az:key-vault) Key Vault `kv-shop-prod` | Connection strings, API keys | Secrets audited and rotated in one place, never in code or app settings. |
| ![Identity](az:managed-identity) [Managed identity](gl:managed-identity) on the API | How the API proves who it is | No password to leak: Azure issues the identity, Key Vault and SQL trust it. [Module 4](module:4) goes deep. |
| ![Storage](az:storage-account) Storage account `stshopimagesprod` | Product images | Pennies per gigabyte, served straight to the browser. |
| ![App Insights](az:application-insights) Application Insights `appi-shop-prod` | Requests, failures, dependencies | One line in the Node app; every request and SQL call gets a duration and a trace. |
| ![Logs](az:log-analytics) Log Analytics workspace `log-shop-prod` | Where telemetry lands | One query language over app, platform and audit logs. Retention is where cost hides. |

## In practice: what it costs

Two honest numbers for the review, from the calculator in [lesson 1.6](lesson:1.6). They are illustrative UK South list prices and change by region and by month; re-run the calculator before you quote them.

| Resource | Starter (~£50-100/month) | Production-ready (~£300-500/month) |
|---|---|---|
| App Service plan | B1 Linux, 1 instance: ~£12 | P1v3, 2 instances, zone-redundant: ~£150-180 |
| Azure SQL Database | S1 (20 DTU): ~£25 | General Purpose 2 vCore, zone-redundant: ~£150-200 |
| Static Web Apps | Free: £0 | Standard (SLA, custom auth): ~£8 |
| Front Door | Not yet: £0 | Standard with WAF: ~£30 plus traffic |
| Storage account | 50 GB LRS: ~£3 | ZRS plus egress: ~£10 |
| Key Vault, Entra ID | ~£1 | ~£2, plus Entra P1 per staff user |
| Monitoring | Inside the 5 GB free tier: ~£5 | 20 GB, 90-day retention: ~£40 |

The gap is not features. It is the [SLA](gl:sla) and the [redundancy](gl:redundancy) from [lesson 1.7](lesson:1.7): Free and Basic tiers carry no meaningful SLA, and [zone-redundant](gl:zone-redundant) compute means at least two Premium instances in different [availability zones](gl:availability-zone). Start on the left, and move a row right only when the business case for that row's nines exists.

> [!WARNING] What goes wrong on day one
> - **Premium left on in dev.** Someone tests P1v3 "for an hour" and it bills for a month. Dev and test get Basic, enforced by the parameter file.
> - **SQL firewall blocks the API.** The database rejects App Service until you allow Azure services or add a private endpoint. It looks like a wrong password; it is not.
> - **Secrets in app settings.** A pasted connection string is visible to anyone with Reader on the app. Key Vault references and a managed identity, from the first deploy.
> - **No [budget](gl:budget) alert.** Put the budget in the same Bicep file as the resources.
> - **Wrong tier or region for zones.** Zone redundancy needs a region with zones *and* a tier that supports them. Check both before promising 99.99%.

## Map it to what you know

| You already run | On Azure |
|---|---|
| IIS or Nginx reverse-proxying to a Node process | App Service on Linux: proxy, process manager and patching are Microsoft's |
| A `.env` file per environment | App settings for plain values; Key Vault references for secrets |
| SQL Server on a VM with a backup job | Azure SQL Database: same engine, backups and failover included |
| A CDN in front of the React bundle | Static Web Apps: build, CDN and certificate in one resource |
| Serilog or console logs on disk | Application Insights: structured, queryable, correlated across API and database |
| "Deploy to the blue box, flip the load balancer" | Deployment slots: deploy to staging, swap |

## Guiding your team

> [!TEAM]
> Questions for the design review:
>
> 1. **Which resource is the bill?** If nobody says "the App Service plan and the database", stop and explain it.
> 2. **Where do secrets live, and who can read them?** The only acceptable answer is Key Vault plus a managed identity.
> 3. **Can we rebuild production from the repository?** If the answer involves the portal, the Bicep file is not finished.
> 4. **What does the starter column cost us in SLA?** Say the number, and write down when it stops being acceptable.
> 5. **What pages someone at 2 a.m.?** An availability test and an alert rule are part of the design, not an afterthought.

## Key takeaways

- The shop is Static Web Apps, App Service on Linux and Azure SQL Database, with Key Vault, a storage account and Application Insights around them, in one resource group in one region.
- The App Service plan is the compute you pay for; apps and slots are tenants on it.
- Secrets go in Key Vault and the API reaches them with a managed identity, never through app settings.
- One Bicep template, three parameter files, three resource groups; production gets its own subscription.
- Starter is roughly £50-100 a month; production-ready is roughly £300-500. The gap is nines, not features.
- AZ-900 is the fundamentals; then AZ-204 or AZ-104, and on to AZ-400, AI-102 or AZ-305.
