## Why this matters

> [!SCENARIO] Two findings and 140,000 passwords
> The loyalty launch is six weeks away. Leo has customer sign-in working in the React Native app against Northline's External ID tenant, but the pre-launch security review returns two findings. The refresh token sits in AsyncStorage as plain text, where a backup or a rooted phone gives it away. And sign-in opens in an embedded web view, which Google refuses: "Continue with Google" fails on every test phone.
>
> Then marketing adds a third problem. Fellside Outdoor's 140,000 customers still sign in through Fellside's Azure AD B2C tenant, and the joint loyalty programme needs them in Northline's.
>
> Priya asks Ana and Leo for a sign-in design that works on web and mobile, stores nothing it shouldn't, and moves Fellside off B2C without making 140,000 people reset their passwords.

## Choosing the sign-in experience

[Lesson 4.4](lesson:4.4) put customers in ![External ID](az:external-identities) [Microsoft Entra External ID](gl:microsoft-entra-external-id). That means an **[external tenant](gl:external-tenant)**: a separate [tenant](gl:tenant) holding only customers, with its own app registrations, branding and sign-in endpoints.

Customers meet a **[user flow](gl:user-flow)**: the sign-up and sign-in journey, configured rather than coded. It picks the methods (email with password, an email one-time passcode, or another [identity provider](gl:identity-provider)) and the sign-up attributes. One flow can serve many apps, but each app gets exactly one. Logic that B2C teams wrote as custom policies becomes **custom authentication extensions**: calls to your own endpoint, such as adding the loyalty number to the token.

**[Social sign-in](gl:social-sign-in)** has rules. An iOS app offering Google or Facebook must also offer a privacy-preserving option, in practice Sign in with Apple. Google refuses sign-in inside embedded web views. And Apple can hide emails behind relay addresses, so never match accounts on email alone.

The bigger choice is where sign-in happens. **Browser-delegated** sign-in opens a Microsoft-hosted, branded page in the system browser. With **[native authentication](gl:native-authentication)**, the app draws its own screens and calls External ID's API.

| | Browser | Native |
|---|---|---|
| Libraries | MSAL or any OpenID Connect library | MSAL on iOS, Android and web |
| Social sign-in | Yes | Yes, via a browser step |
| Single sign-on | Across apps | Only into your own web views |
| Security work | Mostly Microsoft's | Yours too: your code handles passwords |
| On the web | Works as is | No CORS: needs a proxy such as Front Door |

React Native has no native-auth SDK, so you would bridge the native SDKs or call the API yourself. Microsoft rates browser-delegated sign-in as the more secure option. ==Choose native authentication only when the browser step measurably costs you sign-ups.==

## PKCE, MSAL and tokens on the device

Mobile apps and SPAs are **public clients**: anything shipped in them can be extracted, so they hold no client secret. Instead, the authorisation code flow uses **[PKCE](gl:pkce)** (Proof Key for Code Exchange). For each sign-in, the app sends the hash of a random secret and must present the original to redeem the code, so an intercepted code is useless.

**[MSAL](gl:msal)**, the Microsoft Authentication Library, does PKCE, caching and silent renewal for the browser (`@azure/msal-react`), iOS, Android, Node and .NET. There is no official MSAL for React Native, and the best-known community wrapper was archived in 2022. External ID speaks standard OpenID Connect, so Leo uses `react-native-app-auth` (or Expo's `expo-auth-session`), which does PKCE in the system browser.

Sign-in returns an ID token, an access token that lasts about an hour, and a **[refresh token](gl:refresh-token)** that silently gets new ones. It lasts 90 days in a mobile app and 24 hours in an SPA. Each use returns a new one and leaves the old one valid, so delete the old one.

==A refresh token is a 90-day password for one customer: keep it in secure device storage, never in AsyncStorage, logs or crash reports.== **[Secure device storage](gl:secure-device-storage)** means the iOS Keychain and the Android Keystore system, reached through `expo-secure-store` or `react-native-keychain`. Keychain items can survive an uninstall, so clear them on the first launch after a fresh install.

On the web, MSAL keeps tokens in sessionStorage, where an injected script can read them. Add a strict Content Security Policy, or keep tokens server-side behind a [backend for frontend](gl:backend-for-frontend).

## Moving Fellside off B2C

![Azure AD B2C](az:entra-b2c) Azure AD B2C has not been sold to new customers since 1 May 2025. Existing tenants keep working, with support until at least May 2030. Nothing is on fire, but build nothing new on it. There are three routes:

1. **Federate first.** Add Fellside's B2C tenant to Northline's tenant as an OpenID Connect identity provider. This bridge gets joint loyalty working within weeks.
2. **Standard migration.** Import users through Microsoft Graph with random passwords and a migration flag. On a customer's first sign-in, an extension sends the encrypted password to an [Azure Function](gl:azure-functions), which checks it against B2C and stores it in External ID. This is **just-in-time password migration**. Microsoft's migration kit is a preview sample, and some setup uses Graph beta APIs.
3. **High Scale Compatibility mode** keeps both in one tenant, but only for about 5 million objects or more, and it has no social sign-in.

Custom policies must be rebuilt, without guaranteed parity. Every app changes its sign-in authority, so the API accepts both issuers until cutover, and installed apps need a raised [minimum supported app version](gl:minimum-supported-app-version) first.

## In practice

- **Tenant:** `northlinecustomers`, with sign-in at `login.northline.co.uk` through the existing [Azure Front Door](gl:azure-front-door). Only custom [WAF](gl:web-application-firewall) rules are supported on that route.
- **One user flow** for the shop and the app: email with password, Google and Apple.
- **Fellside:** federate now, migrate just in time for six months, cut over with an app release, then delete the B2C tenant.

**What it costs.** External ID bills monthly active users (MAU), counted across every tenant linked to the subscription. The first 50,000 are free, then about $0.03 each (approximate pay-as-you-go list price; varies by region). Northline's 120,000 plus Fellside's 30,000 costs about $3,000 a month. B2C's P1 rate is roughly a ninth of that, so the merge raises Fellside's identity bill. SMS codes cost from a few cents to about 35 cents each.

**What breaks.** Tokens in logs or telemetry, rotated refresh tokens that are kept, a Keychain that signs a reinstalled app in as its previous owner, and old app versions still pointing at B2C.

## Map it to what you know

| You already know | With External ID |
|---|---|
| An Auth0 tenant or Cognito user pool | An external tenant |
| Auth0 Universal Login | A browser-delegated user flow |
| Firebase Auth with your own screens | Native authentication |
| Auth0 Actions | Custom authentication extensions |
| `react-native-auth0` | `react-native-app-auth`, MSAL on the web |
| A Cognito user-migration trigger | Just-in-time password migration |

## Guiding your team

> [!TEAM]
> In a sign-in design review, ask:
>
> 1. **Browser-delegated or native, and why?** Native means more code and more security work for us.
> 2. **Where does each token live on each platform?** A refresh token in AsyncStorage is a stolen account waiting to happen.
> 3. **Does anything sign in through an embedded web view?** Google blocks it, and single sign-on is lost.
> 4. **Which installed app versions still point at B2C?** They can't be forced to update, so the version check comes first.
> 5. **How many monthly active users across all linked tenants?** The free 50,000 is shared.

## Key takeaways

- An external tenant holds customers only, and each app has one user flow.
- Prefer browser-delegated sign-in. Native authentication means your own screens and more of the security work.
- Public clients use PKCE. React Native has no official MSAL, so use a standards library with the system browser.
- Refresh tokens last 90 days on mobile. Keep them in the Keychain or Keystore.
- B2C has had no new sales since May 2025 and is supported until at least May 2030. Federate first, then migrate passwords just in time.
- The first 50,000 monthly active users are free, then about $0.03 each.
